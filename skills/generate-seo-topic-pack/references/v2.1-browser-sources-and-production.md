# SEO v2.1 Browser Sources and Production Gates

## Evidence acquisition order

For Semrush, GSC, Google Trends, and localized SERP, resolve evidence in this order:

1. an authenticated browser live read that matches the planned query and scope;
2. a dated CSV or XLSX export in the project;
3. successful same-day cache;
4. fresh historical cache, followed by explicitly stale discovery-only evidence;
5. `DATA_MISSING` only after the first four tiers were checked.

An absent export is not an availability result. Browser reads must retain the visible account/property, query, filters, market, period, collection time, fields actually observed, source URL, and any limitation. Save the compact structured extraction to the source cache and Research Ledger before another keyword or article is analyzed.

## Semrush v2.1 execution

The account daily total is 5000 units. The Topic Pack thresholds are soft 600, warning 800, and hard 1000. The hard limit has no bypass.

- Run local duplicate, existing-content, and intent clustering gates first.
- Use GSC, Trends, localized SERP, official changelogs, user problems, and the Research Ledger to form no more than the run candidate budget.
- Send no more than the run Semrush query budget of page-level intents to Semrush, using one Primary Keyword and no more than two necessary variants per intent.
- Call `estimate_cost()` before and `record_cost()` immediately after every paid action.
- At 600, only high-priority unresolved decisions continue. At 800, all non-essential work stops. At 1000, all Semrush work stops.
- Never bulk broad-match, re-query synonyms owned by one intent, repeat a keyword for another article, or paginate for extra rows.

## Cannibalization gate

Before external validation, before Briefs, and again before bodies, rebuild `data/seo/historical_article_index.csv` from all article stages and migrated archives. Compare Primary Keyword, Secondary Keywords, Search Intent, title, normalized body, slug, and cluster with `scripts/topic_duplicate_check.py`.

Every candidate receives exactly one decision: `NEW_TOPIC`, `CLUSTER_TOPIC`, `TOPIC_ALREADY_COVERED`, or `CONTENT_REFRESH`. Exact keyword/topic overlap is only a warning. A new page is forbidden only when an existing page owns the same intent and concrete problem. `CLUSTER_TOPIC` requires a distinct sub-problem. `CONTENT_REFRESH` requires recorded change/staleness/quality evidence and is counted separately.

## Validation and publication states

- `FORMAL_VALIDATED`: required current Semrush, Trends, and localized SERP evidence is complete; GSC is attached when available.
- `PROVISIONAL_TODAY`: useful draft backed by partial real evidence.
- `SEO_CONFIDENCE_MEDIUM`: at least two independent reliable demand signals support production despite missing Semrush data.
- `NO_DATA` / `KD_UNAVAILABLE`: literal Semrush result states; neither is an automatic rejection.
- `WAITING_SEMRUSH`, `WAITING_GSC`, `WAITING_TRENDS`, `WAITING_SERP`: source-specific blockers; more than one may apply.
- `FACT_CHECK_REQUIRED`: a product, pricing, model, endpoint, availability, or other factual claim lacks current authorized evidence.
- `TEST_REQUIRED`: technical steps were not run end to end with retained output.
- `SCREENSHOT_REQUIRED`: a real software state or operation needs an authentic screenshot.
- `PUBLISH_READY`: only after formal validation, `evidence-qa`, required real tests/screenshots, and the final platform SEO Review score is at least 85 with no veto. ARTICLE_QA and legacy QA<80 rules do not grant or deny publication.

Partial evidence may produce `PROVISIONAL_TODAY` / `待实测草稿`. It may not be described as formally validated, tested, or publishable.

## Batch production and image planning

Generate all confirmed Briefs first, run one cross-Brief intent audit, then write bodies from cached official facts, the isolated Benchmark, verified product facts, and house style. Do not reopen competitor pages in Writer mode.

After each complete article, use `seo-article-illustrator` for planning only. Every plausible position is `AI_IMAGE`, `AI_IMAGE_OPTIONAL`, `AI_IMAGE_SKIPPED`, `SCREENSHOT_REQUIRED`, or `NO_IMAGE`. Any real Ai Code With, Codex, Claude Code, Semrush, GSC, Google Trends, Feishu, other software, or SaaS interface is `SCREENSHOT_REQUIRED`; never generate or simulate it. Select AI visuals only when they materially improve visual appeal or reading rhythm, create briefs only for final `AI_IMAGE` items, and keep at most three AI images per article after scoring and ranking.
