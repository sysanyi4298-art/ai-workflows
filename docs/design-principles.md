# 工作流设计原则

这套原则在多个项目里反复验证过，是整套 AI 工作流体系的「设计宪法」——
核心是**把 AI 的不确定性关进闸门与预算的笼子里**，同时让每一件事都可回溯。

## 1. 人工闸门优先

付费动作（Semrush 验证、`discover`）与对外动作（发布、外联）都有人工确认节点。
自动化的边界停在「就差一个人点头」之前。

## 2. 证据分层，绝不编造

数据新鲜度、实测状态、产品事实三类证据都必须落盘、可追溯；缺失就标缺失。

- 证据获取优先级：`登录态真实浏览器读取 > 项目导出 > 当日缓存 > 历史缓存 > DATA_MISSING`
- 未真实执行的内容标 `test_status = 待实测`，无证据禁止写「实测 / 亲测 / 已验证成功」
- 产品事实只允许来自事实库文件，缺失写 `FACT_CHECK_REQUIRED`，禁止编造价格 / 模型 / Base URL

## 3. 成本护栏内建

配额守卫 + 单次花费封顶 + 缓存复用（14 天），把 AI 的不确定性关进预算笼子。

- 例：Semrush 操作前先跑配额守卫，保留 10% 余额，分阶段预算（Seed 20% / 候选验证 50% / 跨库 20%）
- 例：`discover` 单次封顶 `$0.15`

## 4. Skill 化与隔离

把「研究」与「写作」分离：研究可读竞品原文，写作不得重开竞争原文、不得把单篇当改写底稿。
避免 AI 把竞品原文直接当改写底稿。

## 5. 一切可归因

外链短码、Run ID、`REFRESH_OF`、历史只读——每篇内容都能回溯到来源与运行。

## 6. 架构冻结

控制层冻结后，日常变化只改数据不改框架，保证流水线稳定可复用。
换赛道只改任务队列的允许字段，无需重构 Skill 与脚本。
